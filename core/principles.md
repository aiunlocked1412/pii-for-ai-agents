# PII Principles

1. **Map before source.** Start with `.project-intel/INDEX.md`, then current state, then relevant knowledge, then source files.
2. **Progressive disclosure.** Load the smallest useful context set: index, overview/current state, relevant Areas and Entities, then source.
3. **Source wins.** PII is compressed understanding; original project files are authoritative.
4. **Agent-first.** Optimize for fast, accurate context routing by future AI agents.
5. **Markdown-first.** Keep knowledge portable, diffable, editable, and vendor-neutral.
6. **Evidence only.** Cite source paths and label uncertainty. Never manufacture project facts.
7. **Dynamic taxonomy.** Derive Areas and Entities from the actual project, including non-software and mixed projects.
8. **Concise knowledge.** Summarize durable facts, relationships, decisions, constraints, and continuity. Do not duplicate documentation or source files.
9. **Incremental maintenance.** Update only knowledge affected by meaningful changes.
10. **No infrastructure dependency.** V1 uses no server, database, cloud account, embeddings, vector search, or API key.
11. **Portable agent support.** Core behavior is agent-neutral; adapters translate only invocation and file format.
12. **Safe coexistence.** Preserve existing instructions and project files. Merge managed content idempotently.
